# t-SNE over posts in the reader constellation (TIN-5680)

Authority: RM10 (TIN-3692 comment bb016df6), R-HOOK-CONVERGENCE-20261004 /
R-N13. TIN-5680 is a child of TIN-2413. Spec: #291
(`docs/agent-notes/2026-10-06-tsne-over-posts-spec.md`, 2ed0c119), option (c).
Base: main 0ed227cc. Production stays default-off behind
`src/lib/flags/constellation.ts`; nothing about the default page changes.

## What landed

- `src/lib/reader/projection/` holds the producer core and the browser view:
  - `text.ts`: term reduction;
  - `embed.ts`: corpus, similarity, edges, warm start, Procrustes, document;
  - `tsne.ts`: exact t-SNE;
  - `scene.ts`: the browser-safe join with routeable posts, plus arrow-key
    navigation.
- `scripts/generate-posts-projection.mts` writes the committed artifact
  `src/lib/data/posts-projection.v1.json`. The recipes are
  `just posts-projection` (warm), `just posts-projection-cold` and
  `just posts-projection-check`.
- `ReaderConstellation.svelte` gains two views, **Similarity map** (SVG, one
  roving tab stop, arrow keys to nearby posts, Escape, `?focus=<slug>`) and
  **Similar posts** (the list equivalent: every placed post with its nearest
  neighbours). The existing Constellation and Year tree views were unchanged
  and still the default. TIN-8628 removed both, see below.

## Decisions

1. **Committed artifact, not generated in CI.** Warm-start stability needs the
   previous coordinates as an input, and a committed file gives a reviewable
   diff when the map moves. The build therefore does no numerical work. CI
   fails when the method or configuration changes without a refit, or when the
   file holds a slug that is not `published: true`
   (`committed-projection.test.ts`). Since TIN-8628 CI also fails when the
   published posts no longer match the committed corpus: a new, edited or
   removed post needs `just posts-projection` and a commit of the result.
   `just check` runs `just posts-projection-check` first.
2. **TypeScript port, not the spear Python.** The method is spear
   `profile/refresh/embed.py` at 1b8b27863f90 (`tfidf-jaccard-exact-tsne-2`):
   the same weights, the same edge rule, the same warm-start rule and the same
   Procrustes step. It is ported so that neither the blog build nor CI needs the
   pinned numpy/scikit-learn shell. The coordinates are reproducible
   (byte-identical for the same inputs on one JS engine) but **not**
   bit-compatible with scikit-learn, because numpy's RandomState is replaced by
   seeded mulberry32 plus Box-Muller. The revision is recorded as
   `tfidf-jaccard-exact-tsne-2/ts-port-1`.
3. **Random init, not PCA.** The spec said `init="pca"`, but scikit-learn
   rejects PCA init with `metric="precomputed"`. spear uses seeded random init,
   and so does this port.
4. **Perplexity 15** (the spec's starting value), capped at (n-1)/3. Title,
   description and tag tokens carry weight 3. The body contributes its top 120
   terms after code, Svelte script/style, markup, link targets and URLs are
   removed. Dates, order, featured state and colour never enter the fit.
5. **No runtime fetch.** The JSON is a static import, about 14 KB minified
   before gzip. With the flag off, nothing renders and nothing is requested.
   Round three replaced the static import with one hashed data file that the
   section fetches lazily. See "Round three" below. With the flag off there is
   still no request.
6. **Plain SVG, not the #288 WebGL engine.** About 140 nodes do not need WebGL,
   and #288 is not merged. Round three draws on a 2D canvas over an inline SVG
   silhouette. It still needs no WebGL.

## First fit (cold, 2026-10-06)

The fit covers 140 published posts and draws 243 edges. KL is 0.2767 and
neighbour overlap at k=3 is 0.679. In a warm-start probe that added one post,
the mean display shift was 0.0099 and the maximum 0.046 (unit square).

## Tap to open and dense clusters (TIN-8628, 2026-11-21)

RM22 (TIN-8594 comment d31d829f) split this out as a blog-only lane.

- Pointers no longer hit node circles. The map picks the node whose centre is
  nearest the pointer (`nearestNode` in `scene.ts`), within 14px for a mouse
  and 28px for touch or pen. A tap never selects a node farther away than
  another node, so dense clusters no longer have overlapping targets.
- Mouse: hover shows the title in the detail panel and a click opens the post.
  Ctrl or Cmd click opens it in a new tab.
- Touch: the first tap selects the node. The detail panel shows its title,
  date and an Open post control. A second tap on the same node, or Open post,
  opens it. A tap away from every node clears the selection.
- Keyboard: unchanged roving tab stop with arrow keys, plus Home and End.
  Enter opens. The focused node announces its title and date.
- Settled by RM26 (TIN-8594 comment 4bb89cf3, 2026-11-22): the operator chose
  "Keep select, then open". The first tap selects and shows the title, date
  and nearby posts. A second tap or the Open post control opens the post. This
  closes the RS9 question about a tap opening a post straight away.

### The design in ten lines

1. A sky panel at full content width: 66 percent of the viewport height on a
   desktop and a tall panel on a phone. It has no border. By day it is a sheet
   of paper. At night its edges fade into the page.
2. One star per post. Colour is the category. Size is length in four steps.
   Glow is recency in three steps.
3. Eleven named constellations, found and named at build time from what their
   posts share: Software, Birding, DevOps, Nature observations, Hardware,
   Personal, Tutorials, Ideas, Making, Photography and Music.
4. Each constellation is drawn as a sparse figure: a minimum spanning tree
   inside the group, without its overlong lines. 121 lines replace 243.
5. A pointer picks the nearest star. Hover shows a card. A click, a tap or
   keyboard focus pins it, with Open and up to three nearby posts as next steps.
   A second click or tap, Enter or Open opens the post.
6. Zoom needs intent: the buttons, a pinch, a double click, or Ctrl or Cmd with
   the wheel. A plain wheel and a one-finger swipe scroll the page. A name flies
   to its constellation. Reset returns.
7. The sky assembles once per session in 0.9 seconds: stars arrive left to
   right, glows and names fade in, figures draw. Reduced motion skips it.
8. One line of copy, a legend that filters, and a How it works popover that
   holds the how-to and the method note.
9. The first paint is the same stars as an inline SVG silhouette in a panel
   that already has its final size. The interactive layer loads over it later.
10. All layout is done by the generator and committed. The browser only applies
    transforms. The session remembers the view, the selection and the filter.

### Decisions

1. **Groups by Ward clustering on the map itself.** The groups are what the
   reader sees, so they are cut from the drawn positions, about twelve posts
   each. A name is the label most of a group shares and few posts outside it
   carry. Two touching groups that earn the same name merge. Tags that say
   nothing about a subject, such as Featured, never name a group.
2. **The map is turned and each axis fills the panel.** The long axis of the
   fit goes across a desktop and down a phone. The phone frame is the desktop
   frame transposed. This is honest only because axes and distances were never
   measurements, and the help says so. No grid is drawn, for the same reason.
3. **Eight hues turned from the theme's primary.** Star colours are
   `oklch(from var(--color-primary-500) L C calc(h + n * 45))` with one
   lightness and chroma for light and one for dark. Paper, ink and accent are
   theme surface and primary tokens. No colour is hard-coded, so all five themes
   work in both modes. A browser without relative colour syntax draws every
   star in the theme's primary. The category is also in the legend, in the card
   and in each star's accessible name, so colour is never the only signal.
4. **Size is word count, glow is recency.** Both are true of the post and cost
   one small integer each. A photo on focus was left out: 92 of the 140 posts
   share a stock header photo, so it would say nothing about the post.
5. **Select, then open, for every pointer.** RM26 ruled this for touch. Round
   three extends it to the mouse, where a click used to open at once, so that
   the card with Open and the nearby posts can be reached. Ctrl or Cmd click
   still opens a new tab.
6. **Zoom needs Ctrl or Cmd, or two fingers.** The map never traps page scroll.
   At rest a drag does nothing and a touch swipe scrolls the page. Once zoomed
   in, a drag pans.
7. **Canvas over an SVG silhouette.** The silhouette is two inline SVGs, one
   per frame, with each star a near zero-length round-capped stroke that does
   not scale. It needs no script. The canvas maps stars onto the same box, and
   its first frame draws them at the silhouette's opacity, so nothing jumps.
   Glows and dust are drawn once into their own canvases and then only moved by
   CSS transforms.
8. **One tab stop for each part.** The Map and List tabs come first in the
   section, so the list is one tab stop and one arrow key away. The stars share
   one roving tab stop, the constellation names another. Arrow keys move
   between nearby stars, Home and End go to the first and last, Enter opens,
   Escape clears, plus and minus zoom.
9. **Type the home page already loads.** The section uses Inter at 600 and 700
   and the body face. An earlier pass used Inter 400, which made the page fetch
   one more font file. That was removed.
10. **No cache header was added.** The data file and the interactive chunk are
    under `/_app/immutable/` with a content hash in their names, so they are
    safe to cache for good. The site has no `_headers` file today. Adding one
    changes caching for the default page, which needs an operator check-in
    under the repository operator notes.
11. **Skip to Latest was removed.** The page navigation above the section
    already links to Latest, and the map now takes few tab stops.

| What | Value |

| Requests the flag adds | 3, all same origin. The default page asks for none of them |
| Home page chunk, loaded with or without the flag | 6,991 bytes gzip, down from 12,141 in round two |

| Script per frame, 140 stars | 0.25 ms on this host |
| Script per frame, 500 stars | 0.9 ms at rest, 1.2 ms zoomed in with titles |

The phone profile is 390 by 844 at 3x, CPU slowed 4 times, 1.6 megabits per
second down and 150 milliseconds round trip.

Frame rate could not be shown on this host. Headless Chromium here has no GPU,
and the page itself, with no flag and nothing moving, takes 33 ms a frame on
the phone profile and 150 ms on the desktop one because of its animated
background. With the CPU at full speed, pan and zoom on the phone profile run
at the same 33 ms median as the idle page. With the CPU slowed 4 times and
every pixel drawn in software they take 83 to 133 ms. The 60 frames per second
budget therefore still needs a real phone. The script cost per frame above is
the part that does not depend on the GPU.
